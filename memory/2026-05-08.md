## Incident Log — 2026-05-08 (Session Compaction)

### Mistake 1: Peptrak checklist not persisting
**Root cause:** The deployed `/app/api/peptrak/route.ts` on GitHub had a PATCH handler that was REPLACING the checklist instead of merging. The local file had the correct merge logic, but the deployed version was the old broken one. Every time a checkbox was clicked, it wiped all other checklist state.
**Fix:** Pushed the correct merge logic to GitHub. Should now work.
**Lesson:** The Vercel deployments were failing silently (SIGTERM) but the GitHub API route was live — meaning the page was calling `/api/peptrak` which hit the broken code in GitHub, NOT the local file. The route.ts on GitHub needs to stay in sync with the local one. When deployments fail, the API still works from GitHub but runs old code.

### Mistake 2: "Also Add Compound" defaulting open
**Root cause:** GitHub had an old version of peptrak/page.tsx where `useState(true)` was set. Local had the correct `useState(false)`. Deployed page was reading from GitHub's version, not local.
**Fix:** Pushed local version to GitHub. `useState(false)` is now correct.
**Lesson:** When I edit local files, I need to also push to GitHub. Vercel pulls from GitHub at build time. If a deploy fails, the live site still serves the previous build which reads from the API (GitHub), not from local files. Everything lives and dies on GitHub being the source of truth.

### Mistake 3: Tesla data appeared missing
**Root cause:** Tesla sessions added to local file (`wlp/data/tesla-charging.json`) were not pushed to GitHub. GitHub had 52 sessions, local had 52 sessions — but local had May 1 ($14.47) and May 7 ($14.24) entries that GitHub didn't have. They were never synced.
**Fix:** Pushed local Tesla data to GitHub, redeployed.
**Lesson:** Any data added to local files MUST be pushed to GitHub the same session. Don't wait. The flow is: local → GitHub → Vercel. Skipping GitHub means the data is gone after container restart.

### Mistake 4: Multiple Vercel deploys timing out
**Root cause:** `npx vercel@latest deploy` was timing out after ~30s during the build phase, returning SIGTERM even though the build was actually running in the background on Vercel's servers.
**Fix:** Re-ran deploy which usually completed successfully on retry.
**Lesson:** The deploy command itself times out in the container but the deployment continues asynchronously on Vercel. Need to check `Aliased:` line to confirm success. Multiple rapid re-deploys can cause cache conflicts.

### Structural issue: GitHub is the real source of truth
Everything that matters — API route logic, page code, data files — must be on GitHub first. Local files are a working copy. Every write to a local data file or code file must be followed by a GitHub push within the same session. The container is ephemeral and can be wiped at any time.
**Rule:** local file change → GitHub push → Vercel deploy. Never skip the GitHub step.
